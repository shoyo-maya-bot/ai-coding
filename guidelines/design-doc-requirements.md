# AI が実装に使う設計書に書いておくこと

AI は書いていないことを推測で埋めます。推測させないために、設計書に次を明記します。

## 共通

- Front Matter: `id`（例: `DOC-BATCH-JOB0001`）、`title`、`type`（batch / api）、`status`（approved になったものだけ実装に使う）
- 実装クラス名（パッケージ + クラス）
- メッセージ表（ID・種別・本文・埋め込み値）
- 使うテーブルと操作（参照 / 登録 / 更新 / 削除）、検索条件、ロックの要否

## バッチ

- ジョブ ID、起動タイミング、起動引数（パラメータファイル名を含む）
- 入力（場所・形式・文字コード・見出し）と出力
- 処理手順を STEP 単位で（STEP 見出しは対応表の `source` から参照される）
- エラー時の扱い（行を飛ばして続行か、全体を止めるか）、終了コード、再実行時の動き（冪等性）
- コミット単位（全件 1 回か、N 件ごとか）

## API

- API ID、メソッド、パス、認証の要否
- 入力項目表（必須・形式・桁・前処理）、出力項目表
- 結果ごとのステータスとメッセージ ID
- OpenAPI がある場合はそのファイル（実装との差分は design-diff で確認）

## 形式

- Excel の設計書は doc-to-markdown で Markdown に変換して使う（結合セル・図形の文字が落ちないか、変換レポートを確認）
- 図は draw.io（編集できる形式）で持ち、Markdown から参照する
